# Pi 1.0.0 棚卸し

取得日: 2026-10-04。本書は変更前の棚卸しスナップショット。後続の変更・検証結果は[移行結果](../issues/2026-10-04-phase-pi-1.0-migration.md)を参照。

## 調査範囲・取得方法

- `pi --version`: 1.0.0。
- 実設定: `~/.pi/agent/settings.json`, `models.json`, `models-store.json`, `mcp.json`, `extensions/`, `~/.pi/providers/kimi-coding/config.json`。
- 共有 MCP 設定はキー名のみ確認し、秘密値は出力していない。`auth.json` は読まず、`pi auth check --provider <provider> --no-refresh --json` で状態のみ確認。
- 配布物同梱 CHANGELOG の関連変更、settings/models/providers/MCP/CLI/prompt-template 文書、関連パッケージの README と package.json を照合。
- npm Registry の全20パッケージの installed/latest version と deprecated メタデータを照会。いずれも installed/latest に deprecated 宣言はなかった。これは機能重複や1.0互換性を保証しない。
- `pi --offline --no-extensions --list-models 'gpt-6'` で利用可能なモデル一覧を確認。拡張を止めたための ollama-cloud 不一致警告は、この診断条件に由来する。
- モデルの実推論、全拡張の再起動・機能試験、各 Git checkout の remote HEAD 比較は未実施。カタログ掲載と提供元での実利用可否は別。
- `~/.pi` は別 Git 作業ツリーで既存の未コミット変更があるため、上書きしていない。

## 結論

### 1. OpenAI: 旧モデルと legacy provider を分けて移行

Pi 0.87.1 は GPT-6 Sol/Luna を追加。0.99.1 は GPT-6.1 Sol を追加し、OpenAI Codex の既定を `gpt-6.1-sol` に変更。0.99.0 は `openai-codex` を **OpenAI Codex (legacy)** と改称し、`openai` の Sign in with ChatGPT を後継とした。

- `gpt-5.6-sol` / `gpt-5.6-luna`: 旧世代だが現行カタログには残る。廃止・利用不能とは断定できない。
- 新規利用の候補: Sol は `gpt-6.1-sol`、Luna は `gpt-6-luna`。
- `enabledModels` が旧 ID を列挙しており、新モデルはモデル循環対象に追加されていない。
- `subagents.agentOverrides.planner` / `oracle` は `openai-codex/gpt-6-astra`。用途・品質比較なしに一律置換はしないが、provider 移行対象として忘れない。
- OpenRouter 側にも 5.6 Sol、Sol Pro、Luna が循環リストに残る。OpenAI 直接接続とは別ルートとして更新する。

**認証上の注意:** 現在 `openai` は ready/api_key、`openai-codex` は ready/oauth。単なる `openai-codex/` → `openai/` 置換はサブスクリプション移行ではなく、既存 API キー利用になり得る。

安全な順序:

1. モデルだけ先に更新する場合は `openai-codex/gpt-6.1-sol` と `openai-codex/gpt-6-luna` を使用し、OAuth ルートを維持。
2. provider 移行は `/login openai` の Sign in with ChatGPT を実施。既存 API キー経路を残す要件を先に確認する。
3. 認証方式と実推論を確認してから enabledModels・subagent overrides を変更。旧認証は動作確認前に削除しない。

### 2. MCP adapter: 標準化の有力候補だが、削除だけでは Kura が消える

0.99.0 から MCP / codemode / tool_search が標準搭載。現在の `pi-mcp-adapter@2.32.1` は `/mcp` を登録するため、セッションの標準 MCP を置き換えている。標準側との二重接続という意味ではない。

現状:

- `misakanet`: `~/.pi/agent/mcp.json`。command/args/cwd の基本形。
- `kura`: `~/.config/mcp/mcp.json`。adapter が読む共有設定。標準 MCP の自動読込対象ではない。
- Kura の `requestTimeoutMs` は adapter 用。標準側では `timeout`（秒）へ単位変換が必要。
- adapter の `mcpScript` と標準 `codemode` は呼出 API が異なる。指示文・子エージェントの allowlist も移行確認が必要。
- adapter には MCP Apps、sampling/elicitation、共有設定読込、lazy lifecycle 等の追加機能がある。標準 MCP は MCP Apps を描画しない。これらを使うなら単純な不要判定はできない。
- adapter の npm latest は 5.0.0。ただしその pi-ai peer range も 1.0.0 を含まない。現行2.32.1の range は `^0.84.1`。無条件の最新版更新ではなく標準移行と比較する。

移行時は Kura の設定を Pi 用ファイルに安全に用意し、タイムアウトを変換し、標準実装で両サーバーを確認してから adapter を外す。共有設定ファイル自体は他クライアント用として保持する。

### 3. pi-transcribe: 明示的な移行案内あり

インストール済み checkout の README が旧 `git:github.com/earendil-works/pi-transcribe` を削除し、`npm:@earendil-works/pi-voice` を導入するよう案内している。機能廃止ではなく配布元・名称の移行。移行後は `/voice-settings` と `transcribe_file` を確認する。`/transcribe` は互換 alias。

### 4. DeepSeek: 手動定義が古いカタログを再追加している

`models.json` に `deepseek-v4-flash` / `deepseek-v4-pro` の手動定義がある。0.86.0 CHANGELOG は旧 Flash aliases の廃止と `deepseek-flash` への変更を記載。現在のキャッシュも `deepseek-flash`（V4.1 Flash）と `deepseek-v4-pro` を掲載する。

- `enabledModels` の `deepseek/deepseek-v4-flash` は `deepseek/deepseek-flash` への更新候補。
- Pro の手動 thinking map は `xhigh: max`、現行カタログは `max: max`。古い価格・能力値の固定も外す候補。
- 標準 `deepseek` は `DEEPSEEK_API_KEY` を扱えるため、独自 endpoint 要件がなければ provider 手動定義全体を削減できる。
- これは直接接続の DeepSeek の話。`ollama-cloud/deepseek-*` の独立した ID に機械適用しない。

### 5. OpenRouter の手動上書きは一括削除しない

`models.json` の15件の Anthropic 上書きは、`agent/bin/refresh-openrouter-overrides.sh` が説明する旧 transport/404 回避策。現在も大半が標準カタログの api/baseUrl/compat と異なる。1.0で問題が解消済みかは実リクエスト未確認。

- `claude-3-haiku` / `claude-opus-4` は現在のキャッシュにないが手動定義に残る。
- `claude-opus-5` は thinkingLevelMap も現行と異なる。
- 再生成スクリプトは15件という件数しか固定しないため、件数が同じでもメンバー入替は検出しない。現在も対象件数は15で、古い上書き集合と同一という保証にはならない。
- 不要になった回避策かを、新しいセッション・標準設定で検証してから削減する。キャッシュ `models-store.json` 自体を手編集してモデル選択を管理しない。

## その他の設定・ローカル拡張

- `settings.json` の一般設定キーに明確な廃止キーは確認できなかった。`subagents` は拡張設定、`lastChangelogVersion` は状態値。
- `defaultThinkingLevel: max` は1.0で有効。旧い値扱いして xhigh に戻す必要はない。
- `theme: dark` は有効。新既定の `system` を使いたい場合だけ変更。
- `tuiMode` 未指定なので1.0では fullscreen。旧 scrollback を望む場合だけ `regular` を追加。
- collapseChangelog=false / treeFilterMode=default / hideThinkingBlock=false / enableSkillCommands=true / editorPaddingX=0 / defaultProjectTrust=ask は既定値の明示であり、削除は任意。deprecated ではない。
- `npmCommand: [pnpm]`, showHardwareCursor=true, terminal.clearOnShrink=true, terminal.showTerminalProgress=true は有効な設定。
- ローカル `stream-watchdog.ts`: #8331 回避策。標準 HTTP timeout と provider event の無活動監視は同一ではない。修正済みの根拠を確認できなかったため維持。
- `bash-default-timeout.ts`: tool_call で未指定 timeout を300秒にする独自方針。標準の既定無期限とは異なり維持候補。
- `herdr-agent-state.ts`: 存在は確認したが今回の廃止・互換性評価は未実施。

## 優先順位

1. OpenAI の利用経路を維持したモデル更新、DeepSeek の古い手動定義の整理。
2. pi-transcribe を pi-voice へ移行。
3. Kura の設定移行と追加機能要件の確認をした上で MCP adapter を標準化。
4. 無効な pi-clarify を除去。Kimi/skills/extmgr/Claude OAuth補助は使用機能に応じて削減。
5. 残す拡張を個別更新・再起動検証。`pi update` 単独は本体のみで、拡張更新は `pi update --extensions`。pin や peer 不一致があるため一括更新だけで完了扱いしない。
